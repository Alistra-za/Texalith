# Release checklist

For whoever cuts a Texalith release: the steps of every release, then the optional work nobody has done yet.

Release from `main` only. The owner's local `master` holds research files in its history and is never pushed.

## Every release

1. `cargo clippy --locked --all-targets -- -D warnings` and `cargo test --locked --no-fail-fast -- --test-threads=2` pass locally. Do not run the tests while a bake is using the GPU.
2. The Tessalith `rev` in `Cargo.toml` (the same on all three lines) is the commit the build was tested against, and it is on GitHub.
3. `CHANGELOG.md`: rename the top section from `(Unreleased)` to the version, one line per user-visible change.
4. `Cargo.toml` `version` matches. Build once so `Cargo.lock` follows.
5. `README.md` and `docs/Guide.md` describe this build: every UI name copied from the app, nothing about earlier versions (history lives in the changelog).
6. If dependencies changed: `cargo about generate --frozen -c about.toml about.hbs -o THIRD_PARTY_LICENSES.md`, and update `THIRD_PARTY_NOTICES.md` for anything that is not a crate.
7. If the emblem (`docs/assets/texalith-emblem.png`, hand-made) changed: `py -3 -I tools/make_icon.py` cuts the icon files in `assets` from its X.
8. If the Community Shaders copy was re-pinned: `assets/cs-shaders/PIN.toml` and the files in `assets/cs-shaders/licenses` match the new build.
9. Commit, push, and wait for the **CI** workflow to pass.
10. Tag `v<version>` and push the tag. The **Release build** workflow uploads `Texalith-<version>-win-x64.zip` and `SHA256SUMS.txt` as an artifact.
11. Download the artifact, unzip it to a new folder, run `texalith.exe`, and save one map from each tab.
12. Create the GitHub release from the tag by hand: attach the zip and `SHA256SUMS.txt`, paste the version's changelog section.

## Optional, not done

- Formatting: `cargo fmt --check` differs in about 50 files, so CI does not gate on it. One `cargo fmt` commit would let it.
- Screenshots for the README and guide, generated by a test as Tessalith's are.
- Code signing. Without it SmartScreen warns on first run.
